# 课堂演示业务范围

v2.1，2026-11-18。题目保持面向连锁餐饮的生鲜食材仓储与配送管理系统。目标是用真实数据库演示一条完整流程，建立在原 WMS 和已通过的 P0/P1 上。

## 角色与目标受众

教师和同学观看演示；总部、仓管负责基础资料、入库、库存查询、选批出库和配送状态登记。门店资料体现配送去向；P1 的门店账号和隔离继续保留，仅有本店已授权只读数据，不新建门店操作端。无角色账号默认拒绝。

## 基础模块范围 D1

课堂演示使用的商品、供应商、门店、仓库、库区、储位须能按需要查询、新增、修改；演示涉及字段有必填校验，编码等业务唯一字段在新增和修改时由后端校验（修改排除当前记录自身），启用/禁用状态能保存并实际约束后续操作。删除已被单据、库存或下级资料引用的主数据时应拒绝或提供明确的安全处理，不可造成悬空引用。

明确补齐五项：仓库按名称、属性、状态筛选；库区编码新增/修改唯一校验；库区列表禁用；储位按编码、所属仓库、所属库区筛选；储位启用和禁用。禁用仓库、库区或储位后，不得作为新上架的目标位置；历史资料和库存仍可查看。单纯禁用不得自动清空、搬移库存，也不得误锁住已在有效位置且满足其他条件的现有库存出库。

## 必做流程

食材及供应商、门店建档 → 批次入库 → 收货上架 → 库存与效期查询 → 仓管选择门店、批次和数量 → 确认出库 → 待配送 → 配送中 → 已送达 → 查询批次和配送记录。

复用 P1 的食材规格、单位、温区、临期阈值、供应商、门店和账号绑定。新增批次事实必须关联供应商、食材、生产日期、到期日期及入库记录；批次键需区分不同供应商的同名批号。不同批次不得合并，历史批次日期不随食材资料修改。

收货一次增加实际数量，上架在原库位减、目标库位加，全仓不增量，批次不丢。收货不得超计划，重试不得重复入账；上架到正式储位需温区匹配。只接收满足日期和来源规则的正常演示批次，不扩展不合格验收、冻结解冻及隔离处置流程；原有不可用库存仍须排除。

出库由总部或仓管人工选批，允许一单多条明细。草稿不占库存。确认出库时重新检查门店和食材启用状态、来源日期、正式可出储位、当前可用量和数量规则；任一行失败整单不扣。成功时在同一事务扣账、写逐批流水、固定出库事实并创建唯一待配送单。

配送单关联出库单、目标门店、地址快照、批次食材数量，填写配送员和联系方式，可附备注。进入配送中前须有配送员信息；仓管确认送达，记录操作者和时间。确认送达表示仓管登记的物流状态，不是门店逐批验收事实。配送状态变化不再改变库存。已出库后不支持编辑批次数量、取消回库或退货。

## 数量与日期规则

- 固定规格，例如鸡胸肉 1kg/袋。业务动作数量为正整数 1..2147483647；拒绝空值、0、负数、小数和越界，不静默取整。余额可为 0，流水可为负；累计用 long 等足够宽类型校验后写回。
- 延续原库存账：在库＝未分配＋已分配；不得另建生鲜余额表。简化出库仅使用满足条件的未分配库存；扣在库和未分配相同数量，旧占用保持不变。
- 可出库量须过滤过期、质量不可用、非正式储位、缺来源日期和历史待核验批次。历史库存差额不自动平账，旧占用不直接清零。演示使用正常入库产生的新数据。
- 时区 Asia/Shanghai。生产日不得晚于收货日，到期日晚于生产日且晚于收货日。到期当天按本课设约定不可出库。
- 剩余天数＝到期日－业务当日；≤0 过期；0＜剩余≤食材阈值临期；其余正常。出库当日实时复验，不依赖定时任务。不增加计划送达日约束。
- 从同一批次多个明细出库时合计检查库存，避免逐行校验通过后超扣。库存与流水及关联单据原子提交；重复同单确认不能二次扣库，换请求键也不能绕过单据终态。

## 查询和边界

库存列表展示批次、供应商、位置、数量、效期和临期状态；配送详情展示门店、地址快照、食材、批次、数量、配送员及状态时间。可由批次查入库来源及出库/配送记录；不要求独立复杂追溯大屏。不同单位数量不相加为无意义总量。

本次不做 AI、门店申领审批、自动 FEFO、波次拣货、门店签收及拒收短缺、退货回仓、门店库存账、设备接入、地图路线、复杂看板。保留旧源码，演示角色隐藏无关或不可运行入口。

完成标准是 validation.md 的 D1/D2/D3/D4 必测通过、最终版本本机可重复启动，并可按同一套业务数据完整演示。尚未通过时如实标记，不沿用旧 P2～P7 的全量要求或完成称谓。
