# 出库与配送状态合同

v2.1，2026-11-18。本文件是待实施规则，替代旧 v1.2 发车扣账、申领和签收合同；P0/P1 冻结记录保持原状。实施时复用原枚举能表达的状态，在接口合同中列出逻辑状态到实际字段的映射，避免伪装已有流程完成。

| 对象及动作 | 前置条件 | 结果与库存影响 |
|---|---|---|
| 入库收货 | 合法计划、日期、来源及正整数数量，未超累计计划 | 收货暂存库存增加一次，同时记录任务与流水 |
| 上架 | 仓库、库区、储位均启用；正式储位温区匹配，未超剩余待上架量 | 同批次从暂存移至正式位，全仓数量不变 |
| 出库草稿 | 总部或仓管指定启用门店、食材、库存批次、数量 | 可编辑或删除；不占用库存，不创建配送单 |
| 确认出库 | 草稿有效；全部明细满足出库当日效期、来源和未分配库存要求 | 同事务扣在库及未分配、保留旧占用、写逐批流水、出库变已出库、创建唯一待配送单 |
| 编辑配送资料 | 待配送，总部或仓管 | 填配送员、联系方式；门店地址快照和出库批次数量不可改；不扣库 |
| 开始配送 | 待配送且已填配送员及联系方式 | 变配送中，记录操作人和时间，不扣库 |
| 确认送达 | 配送中，总部或仓管 | 变已送达，记录操作人和时间，不扣库；属于仓管登记 |

已出库为库存事实终态，已送达为配送终态。不可普通编辑状态、批次或数量，不可从待配送直接送达，不可倒退；重复已成功动作返回既有结果或明确已处理，库存与单据不重复。出库与配送一对一关系由数据库唯一约束保障。

## 事务与旧入口

确认出库的库存、流水、出库状态、配送主明细须整体成功或整体回滚；同批多行先汇总校验，采用条件更新或必要行锁避免负库存。复用原库存服务并补齐批次参数，不通过页面直接修改余额，不引入另一套库存账。可以新增简单业务动作，但不得同时调用旧发货再扣第二次。

旧分配失败占位、波次 TODO 不再是课堂流程的前置条件；旧拣货/发货存在空批次问题，若复用其代码必须修复所用路径。旧 CRUD、导入和发货不能绕过新单据保护；对本次角色关闭无用入口或统一受保护动作。普通 edit 不允许写库存余额和动作状态。

禁用仓库、库区或储位阻止将其用于新的上架/入库目标，但不删除历史记录、不搬移已有库存；已有库存是否可出库仍按批次、质量、效期、正式位置和可用量等既定条件判断，禁用状态本身不应错误地冻结该库存。所有写动作由后端校验角色、当前状态及数据范围；门店账号保留本店只读，不因隐藏按钮而省去服务端鉴权。禁用门店阻止新草稿/新出库，但不阻断已经出库的配送记录读取和仓管完成配送。

本次不设申领、预分配、独立拣货、门店逐批签收、取消回库和异常终止。此删减避免产生待释放占用和拣货后隔离的复杂状态；已存在的旧占用不由新流程擅自释放。
