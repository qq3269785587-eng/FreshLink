## 启动

双击根目录 `Start-FreshLink.cmd`；旧名称 `Start-WMS.cmd` 仅转调新入口。脚本启动项目 Redis、前端和后端，检查首页及验证码接口就绪后打开浏览器。

不打开浏览器时，从项目根目录执行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\Start-Project.ps1 -NoBrowser
```

默认地址：前端 `http://127.0.0.1:3100/`；后端 `http://127.0.0.1:8080/jeecg-boot`；Redis `127.0.0.1:6379`。若端口由其他目录的进程占用，当前脚本拒绝把它当成 FreshLink。先查明归属，不批量结束所有 Java/Node 进程。

当前后台进程日志在根目录 `logs/`；Redis 的自身启动日志仍在 `runtime/redis/`。启动后端把构建 JAR 复制到 `runtime/run/jeecg-system-start.jar`，工作目录设为 `runtime`，配合原 logback 的 `../logs` 输出到根日志目录。

## 构建

从项目根执行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\Build-Backend.ps1 -Offline
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\Build-Frontend.ps1
```

后端缺少缓存依赖时，核查报错后去掉 `-Offline`，下载仍使用本项目 Maven 仓库；不要改成 C 盘默认缓存。前端构建调用现有 `npm run build`，不执行安装或升级。新增依赖的安装命令需显式指定项目缓存/store 并保留锁文件。

后端构建脚本仍只打包；P0 新增 `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\Test-Fresh.ps1`，通过明确的 `p0-tests` profile 运行审查过的 fresh 服务测试，并调用前端 `npm run fresh:test`。默认 package 不等于测试通过。重新构建不会自动替换运行中的 JAR，需确认项目进程归属后重启。完整业务验收另按 `specs/生鲜课设改造/validation.md` 执行。

迁移保留了原有 pnpm 版本差异：`runtime/tools` 内工具为 10.34.9，前端依赖元数据记录为 11.25.0。当前构建已验证可用，本次未重装或升级依赖；P0 在新增依赖前先确定实际包管理器版本，不直接按旧工具覆盖现有依赖。
