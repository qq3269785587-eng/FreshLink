# FreshLink 前端与联调任务书

版本 v2.1 · 2026-11-18 · 两天课堂演示版

项目题目：面向连锁餐饮的生鲜食材仓储与配送管理系统。

两天内以课堂演示为目标，在原 WMS 和已验收的 P0、P1 上先补齐演示范围内的基础功能，再跑通生鲜入库、库存效期、人工选批出库与简单配送。D1、D2、D3、D4 均待实施；P0、P1 保持已验收状态。本任务书替代旧 P2～P7 安排。

## 工作范围与协作

阶段分支建议：D1 使用 `feat/a-d1-basics`（A）/`feat/b-d1-basics`（B）；D2 使用 `feat/a-d2-inbound` / `feat/b-d2-inbound`；D3 使用 `feat/a-d3-delivery` / `feat/b-d3-delivery`；D4 使用 `feat/a-d4-demo` / `feat/b-d4-demo`。每个阶段完成本人部分、自测并提交 PR，负责人合并后，从最新 main 开始下一阶段。


你负责 apps/web、页面和 API 接入、浏览器联调、演示数据操作步骤及讲解材料。后端同学负责数据库、接口、事务及后端权限。共享文件先约定归属，保留对方修改。你完成每阶段后提交、推送本人分支并开 PR，负责人审查和合并；最终组合版本由负责人验收。

本次保留一个配送中心、多个门店、固定包装整数计数。总部或仓管统一操作，门店账号保留 P1 本店只读权限。

AI、门店申领审批、自动 FEFO、波次拣货、门店逐批签收、拒收短缺、退货、门店库存、IoT、地图、复杂看板和全新机器部署移出本次必做。保留旧代码，隐藏无关或不可运行入口。基础资料页面纳入必做范围，检查商品、供应商、门店、仓库、库区、储位的查询、新增、修改、必填/重复校验和状态实际生效；禁用仓库、库区或储位不得用于新的上架，历史记录仍可查，不能因此误拦已有库存的出库或已出库配送。删除主数据时按现有引用关系保护，避免破坏历史单据。

确认出库是唯一扣库存动作：同一事务按批扣账、记录流水、锁定出库事实并生成唯一待配送单。配送仅“待配送 → 配送中 → 已送达”，状态变化不再扣库。送达是仓管登记，不宣称门店签收；已出库不允许改数量或取消回库。

后端先给最小接口合同，你确认字段、错误提示和状态后即可并行做页面。接口未就绪可以临时做页面骨架，但提交验收必须接真实接口，临时数据不能混入演示结果。每天集中联调。

代码仓库：https://github.com/yukisuki7/FreshLink。代码基线为 p1-accepted；它不含本次新规格。开工前先等负责人将规格文档 PR 合入 main，并确认 main 已含 specs v2.1，再从最新 main 创建本人阶段分支，不检出旧标签覆盖新文档。仓库无写权限时，fork 后从个人 fork 开分支并向上游仓库提 PR。

团队克隆目录即工作根，使用根 README、docs/团队本机开发指南.md 和 scripts/team/ 配置自己的数据库及账号，不照搬原机固定库名、密码或端口。下载和缓存放项目内，不放 C 盘。首次写入前核验实际库、后端构建和前端代理，不能用原业务库做测试。

## 两天要完成的页面

### D1 · 基础页面补全（第一天上午）

- 仓库筛选提供名称、属性、状态并可组合查询；清空后恢复列表。
- 库区列表提供禁用操作；编码新增/修改的唯一校验展示后端返回结果（修改自身编码可保存，改成他人编码应提示重复）。
- 储位筛选提供储位编码、所属仓库、所属库区；库区选项随仓库联动或过滤。
- 储位列表提供启用/禁用状态操作和确认反馈。
- 核查商品、供应商、门店、仓库、库区、储位演示用页面的查询、新增、修改、必填/重复提示及状态展示；验证禁用仓/区/位不能用于新上架，历史记录仍能查，已有库存出库及已出库配送不被错误阻断。
- 复用现有组件和 API 模式，只补演示流程缺口，不重做整套视觉；D1 页面接真实后端，后端未就绪的页面仅可临时 mock，不纳入阶段完成。



两天按 D1→D2→D3→D4 推进：第一天上午 D1 基础页面，下午 D2 入库效期；第二天上午 D3 出库配送，下午 D4 最终联调、修复和演示彩排。复用原 BasicTable、表单、弹窗和字典组件，不重做整套视觉。

- D2 入库：在原流程展示或补充供应商、批号、生产日期、到期日期和数量，接通真实保存、收货、上架；页面刷新后仍能读取。日期和数量前端校验用于提示，最终由后端校验。
- D2 库存：显示食材规格单位、供应商、批次、位置、库存和日期；用清楚的标签区分正常、临期、过期，支持基本筛选。不可出库批次给出原因；不把账面未分配直接当可出库量。
- D3 出库：仓管选择门店和可用批次、输入数量，展示选中批次及可用量。草稿不占库存，确认按钮说明本次将扣库存并生成配送单；提交后刷新真实结果，处理库存不足、过期和重复操作提示。
- D3 配送：列表与详情展示单号、关联出库、门店地址快照、批次食材数量、配送员联系方式、状态和时间。待配送填写资料后“开始配送”，配送中“确认送达”，已送达只读；不增加门店签收表单。
- 查询展示：从配送详情能看到来源批次，从批次能查入库及出库配送记录；可复用详情弹窗或列表链接，不另建复杂追溯大屏。

按钮权限、加载与提交禁用态按真实状态显示；前端防连点不能代替后端幂等。已出库数量和门店地址快照不可直接编辑；后续配送按钮不能再次调用原出库/发货扣库存接口。

第二天完成 D3 联调和 D4 演示收口。菜单突出基础资料、入库、库存效期、出库、配送；系统题目一致，隐藏无关死入口。统计仅使用可核对的真实数据，不合计不同单位库存，不补假看板。

## 验证与演示交付

### D1 基础模块用例（B 前端）

- D1-01 仓库名称、属性、状态组合筛选及清空查询。
- D1-02 新增重复库区编码显示后端拒绝；修改保留自身编码可保存、改成其他记录编码提示重复。
- D1-03 库区列表禁用，操作反馈与刷新后的状态正确。
- D1-04 储位编码、所属仓库、所属库区组合筛选；仓库切换后库区选择正确更新。
- D1-05 储位启用/禁用操作、确认及刷新后的显示。
- D1-06 抽查商品、供应商、门店、仓库、库区、储位新增/修改、必填/重复提示、状态展示及被引用记录删除保护。
- D1-07 页面展示禁用仓区位不用于新上架；历史库存是否可出库仍按有效期、来源、未占用等规则显示，不因行政禁用本身冻结；已出库配送仍可继续完成。



按 specs/生鲜课设改造/validation.md 执行页面对应的 D2/D3 用例；与后端一起核对 API、数据库和页面结果。D4 负责实际浏览器全链操作、启动说明和演示脚本，使用同一套数据串联，不拼接多套截图。

- 正常流程：食材和门店资料 → 批次入库 → 收货上架 → 库存与临期 → 人工选批出库 → 配送登记 → 开始配送 → 确认送达 → 查询记录。
- 数量核对：B1入10袋、B2入20袋，上架后30；B1出6后总量24、B1余4；开始配送及送达后仍24。
- 反例：过期批次不能出库，库存不足整单失败；页面显示具体原因，刷新后余额不变。另检查重复确认不会增加配送单或二次扣库、状态不能跳级。
- 权限：总部和仓管可执行各自获授权的仓储配送操作；门店仅见本店获授权数据，不出现新写操作；直接接口越权由后端拒绝，配合复验 P1 隔离。
- D4-01～04：最终前端生产构建、受影响测试及类型诊断比较；真实完整演示；本机关闭重启可用；标题、菜单、错误态、空态和说明完整。历史类型诊断不冒称全量检查通过。
