# D1 基础资料接口合同（A 提案，待 B 确认）

基线为 v2.1 main 的 b2c4c49。下列路径相对后端上下文 /jeecg-boot。仓库已有基础资料 CRUD；组合筛选、校验及状态动作按下表联调，功能完成情况以 D1 自测记录为准。

| 资料 | 路径前缀 | D1 页面与接口约定 |
| --- | --- | --- |
| 仓库 | /warehouse/wmsWarehouses | GET /list 接受 warehouseName（包含匹配）、warehouseAttr（字典编码）、status（字典编码），按 AND 组合。返回 id、warehouseCode、warehouseName、warehouseAttr、status。 |
| 库区 | /warehouse/wmsStorageZones | 列表可按 warehouseId 查。新增和修改沿用 zoneCode、zoneName、warehouseId、zoneType、storageType、isSellable、status。zoneCode 全局唯一，修改用 id 排除自身。拟补 PUT /disable。 |
| 储位 | /warehouse/wmsStorageLocations | GET /list 接受 locationCode（包含匹配）、warehouseId、zoneId（精确匹配），按 AND 组合。行中保留 id、locationCode、warehouseId、zoneId、status 和原有关联名称。拟补 PUT /enable、PUT /disable。 |
| 商品 | /goods/wmsProducts | 沿用 P1 表单及 productCode、productName、productSpec 等原字段和原编辑接口。 |
| 供应商 | /fresh/suppliers | 沿用 keyword、status 筛选，行中使用 supplierCode、supplierName、status 及原联系字段。 |
| 门店 | /fresh/stores | 沿用 keyword、status 筛选，行中使用 storeCode、storeName、address、status 及原联系字段。门店账号沿用本店查询权限。 |

**列表与写入。** GET /list 使用 pageNo（从 1 起）、pageSize（默认 10）。清空筛选时省略条件并回到第一页。切换仓库时清空 zoneId，按新的 warehouseId 获取库区选项。读取 result.records 与 result.total。新增用 POST /add，修改用 PUT /edit 并带 id，单条删除用 DELETE /delete?id=… 。已有表单继续提交原必填项。

**状态动作。** 仓库已有启禁用动作，库区、储位拟沿用同一调用方式。例如 PUT /warehouse/wmsStorageLocations/disable 的 JSON 为 {"id":"L01"}。服务器按 id 更新，客户端在 success 为 true 后重查列表。仓区位状态提交字符串 CREATED（创建）、ACTIVE（启用）或 INACTIVE（禁用），仅 ACTIVE 可作为新上架目标。供应商、门店沿用 ACTIVE、INACTIVE。页面展示字典中文，筛选传编码。操作权限沿用对应资料的编辑权限，总部、仓管按授权操作，门店保留 P1 本店只读范围。

**失败反馈。** 客户端同时处理 HTTP 错误与业务失败，显示后端 message。拟定校验示例为 {"success":false,"message":"库区编码已存在"}（仅列相关字段）。保存失败时保留表单，原记录不变。被历史记录引用时拒绝删除并说明原因。新上架须在服务端检查目标仓库、库区和储位；提示具体哪个对象未启用。禁用后仍可查历史，已有库存按原出库资格判断，已出库配送可继续。

D1 的状态操作不传数量，也不改库存。请 B 核对两处文本筛选的匹配方式、三个拟补状态动作的路径及状态编码，有差异时指出具体页面和字段；双方确认后按此实现。
