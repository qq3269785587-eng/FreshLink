# FreshLink D3 人工选批出库与配送接口

基线为已合并 D2 的 `main@2647c0f`。接口路径相对于后端 `/jeecg-boot`，响应使用 JEECG `Result`。业务成功以 `success: true` 为准，失败提示读 `message`。下表中的字段位于 `result`。

## 仓管出库

| 操作 | 请求 | 结果 |
| --- | --- | --- |
| 门店选项 | `GET /fresh/stores/options` | 启用门店 |
| 库存列表 | `GET /inventory/wmsInventory/list` | 复用 D2 库存查询。选批使用记录的 `id`、`stockBatchKey`、`eligibleQuantity`。显示供应商、`batchNumber`、规格单位、正式储位及到期日。 |
| 出库列表 | `GET /fresh/outbounds?pageNo=1&pageSize=10` | `{records,total,current,size}`，可选 `storeId`、`status`、`stockBatchKey`。 |
| 出库详情 | `GET /fresh/outbounds/{id}` | `{order,lines,deliveryId}`，草稿的 `deliveryId` 为空。 |
| 新建草稿 | `POST /fresh/outbounds` | 返回出库详情 |
| 编辑草稿 | `PUT /fresh/outbounds/{id}` | 完整替换门店及明细，返回出库详情。只允许草稿。 |
| 删除草稿 | `DELETE /fresh/outbounds/{id}` | 删除草稿及其明细 |
| 确认出库 | `POST /fresh/outbounds/{id}/confirm` | 返回已出库详情和唯一配送单 ID。重复确认返回同一结果。 |

建单、编辑的 JSON 均为 `{storeId,lines:[{inventoryId,stockBatchKey,quantity}]}`。提交 1 到 100 条明细，数量为 1 到 2147483647 的 JSON 整数。同一库存行多条合为一条并检查合计。页面可以用 `eligibleQuantity` 给出即时提示，确认时由后端重新验证。

`order` 含 `id`、`orderNumber`、`storeId`、`storeName`、`status`、`createdBy/createdAt`、`confirmedBy/confirmedAt`。`status` 为 `DRAFT`（草稿）或 `CONFIRMED`（已出库）。`lines` 含 `id`、`inventoryId`、`stockBatchKey`、`productId`、`productName`、`productSpec`、`unit`、`supplierId`、`supplierName`、`batchNumber`、`locationCode`、`expiryDate`、`quantity`。效期日期为 `YYYY-MM-DD`。

草稿不占库存。确认出库重验当前门店、食材、批次来源、效期、良品正式位和未分配量。在同一事务扣在库与未分配、保存负数流水、固定出库单和明细并创建待配送单。已有占用保持不变。流水的 `reference_number` 是 `orderNumber`，`batch_number` 是内部批次键。出库失败后保留草稿，操作员可刷新库存并改数量。已出库仅可查询或重复确认。

## 配送

| 操作 | 请求 | 结果 |
| --- | --- | --- |
| 配送列表 | `GET /fresh/deliveries?pageNo=1&pageSize=10` | 分页 `records`、`total`、`current`、`size` |
| 配送详情 | `GET /fresh/deliveries/{id}` | 配送单及 `items` |
| 填配送员资料 | `PUT /fresh/deliveries/{id}/dispatch-info` | JSON `{driverName,driverPhone,remark}`，前两项必填，备注可选，仅待配送可编辑。 |
| 开始配送 | `POST /fresh/deliveries/{id}/start` | 已填配送资料时 `PENDING`（待配送）→ `IN_TRANSIT`（配送中） |
| 确认送达 | `POST /fresh/deliveries/{id}/deliver` | `IN_TRANSIT` → `DELIVERED`（已送达） |

配送返回 `id`、`outboundId`、`outboundNumber`、`storeId`、`storeName`、`storeAddress`、`status`、配送资料、`createdBy/createdAt`、`dispatchBy/dispatchAt`、`deliveredBy/deliveredAt`。详情的 `items` 来自已确认的出库明细。门店名称和地址以确认出库时快照为准。配送动作只改配送资料或状态，返回更新后的配送详情。

总部与仓管可操作。门店账号只读本店配送，直接访问其它店配送或任何写接口会失败。门店禁用后禁止新建草稿和确认现有草稿。已出库的配送仍可查并完成。旧发货、波次和通用出库编辑接口与 D3 单据及批次扣账分开。

## 数据库与本地验证

在 D2 库备份后，按顺序执行 `apps/backend/db/fresh/D3_00_outbound.sql` 和 `D3_01_delivery.sql`，再启动 D3 后端。新建团队库时初始化脚本按序执行。D3 业务数据产生后，应用回退须先确定数据库恢复点，避免遗漏已经扣减的库存及关联配送记录。

后端测试使用 `mvn -Pp0-tests -pl jeecg-module-system/jeecg-system-start -am package`，本机路径与配置按团队开发指南。D3 浏览器页面和演示菜单由 B 侧按此合同接入。

HTTP 探针与 D2 使用同一组环境变量。初始化独立的 `freshlink_d3_*` 测试库，在该库导入一次 `scripts/team/fixtures/D2-isolated-negative-data.sql` 准备过期和历史待核验库存，以仓管账号登录取得访问令牌和 ID，设置 `FRESHLINK_API_ROOT`、`FRESHLINK_ACCESS_TOKEN`、`FRESHLINK_OPERATOR_ID`、`FRESHLINK_EVIDENCE_DIR` 后运行 `python scripts/Invoke-FreshD3ApiProbe.py`。如需门店读权限用例，提供 `D3_STORE_A_TOKEN` 与 `D3_STORE_B_TOKEN`。正常库存由探针通过入库和上架接口建立。
