# FreshLink D2 入库与效期接口合同

基线为 v2.1 与远端 main 的 D1 合并版本 `f2a5743`。复用原入库、收货任务、上架任务和库存页面接口。总部、仓管可用，门店权限沿用 P1。JEECG 响应保持 `Result` 格式，前端以 `success` 和 `message` 判断结果。

| 动作 | 接口及请求 | 状态与数据 |
| --- | --- | --- |
| 保存计划 | `POST /inorder/wmsStockInOrders/add` 或 `PUT /inorder/wmsStockInOrders/edit`，在现有表单加 `supplierId`，每条 `wmsStockInOrderItemsList` 明细传 `productId`、`expectedQuantity`、`batchNumber`、`productionDate`、`expiryDate` | 一条明细指定一个供应商批次。原提交审核、审核和明细查询接口保留。 |
| 创建收货任务 | `POST /inorder/receiveTasks/add`，沿用 `orderIds`、`operator` | 单据 `APPROVED` → `RECEIVING`，生成各明细任务。 |
| 收货 | `POST /inorder/receiveTasks/addRecords`，JSON `{id, execQuantity, targetLocationCode, requestKey}` | `id` 是任务 ID。目标为该仓启用的良品收货位。批次和日期由入库明细读取。全单收完成为 `RECEIVED`，生成上架任务。 |
| 上架 | `POST /inorder/putawayTasks/addRecords`，JSON `{id, execQuantity, targetLocationCode, requestKey}` | 来源储位由任务确定。目标为启用且温区匹配的良品正式储位（存储位/拣选位）。状态为 `PUTAWAYING` 或 `PUTAWAYED`。 |
| 查询库存 | `GET /inventory/wmsInventory/list`，沿用分页 | 返回商品、来源供应商、批号、生产及到期日、入库引用、位置和数量。 |

日期用 `YYYY-MM-DD`，按 Asia/Shanghai 当日验证。收货时生产日不得晚于当日，到期日晚于生产日和当日。正向数量为 JSON 整数 1～2147483647，整张入库单计划合计不得超过 2147483647。收货和上架可分次，同一次请求重试须复用同一个 `requestKey`（建议 UUID），新的分批动作使用新键。相同任务键和参数重试返回成功，换参数复用请求键会返回业务错误。服务端从任务和单据读取商品、批次、日期及来源位置。

库存效期状态为 `EXPIRED`（剩余天数≤0）、`NEAR_EXPIRY`（大于0且不超过阈值）、`NORMAL` 和 `PENDING_VERIFICATION`（历史缺来源）。库存账面未分配量是 `availableQuantity`，符合出库资格的数量是 `eligibleQuantity`。D3 使用库存行 ID 与内部 `stockBatchKey` 识别库存批次，界面展示供应商 `batchNumber`。
